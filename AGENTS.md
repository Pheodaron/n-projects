# Agent Guidelines: Go Application Architecture & Design

Ты выступаешь в роли Go-dev architect. Твой главный приоритет — **простота, идиоматичность и читаемость кода**. Не усложняй систему без явной необходимости.

---

## 1. Общее

- проект должен быть простым, понятным и человекочитаемым, без overengeneering
- структура должна следовать основному layout golang приложений, но при этом внутри internal иметь feature-first структуру
- код должен учитывать особенности golang и опредлеять архитектуру свойственную golang приложения и придерживаться философии golang
- основные системные зависимости должны устанавливаться через mise
- основные скрипты для запуска, сборки и прочих взаимодействий с проектом должны запускаться через mise

## Структура и команды проекта

- Соблюдать простоту, идиоматичный Go и feature-first структуру внутри internal.
- Репозиторий — monorepo: клиенты в apps/, серверные сервисы в apps_back/. У каждого приложения свой mise.toml, Go-модуль и Docker build context; у каждого backend-сервиса свой Dockerfile. В корне нет Go-модуля и workspace; приложения не используют локальные replace друг на друга. Общий proto/ генерируется в internal/gen каждого приложения.
- Общие инструменты и команды определять в корневом mise.toml; команды приложения — в его mise.toml. Desktop использует Wails3 CLI, устанавливаемый mise через go install.
- Backend-сервисы запускать через общий compose.yaml из корня; каждый образ собирать отдельно через Dockerfile сервиса, без build в Compose. Wails остаётся отдельным клиентом.
- В корне оставлять только README.md и AGENTS.md из Markdown-документов; остальные Markdown-документы хранить в docs/.
- Миграции Goose хранить в migrations/ и запускать из корня проекта; не применять их автоматически в backend или отдельном сервисе Compose.

## Документация env

Единственное место описания переменных окружения — комментарии в .env.example. При изменении env-контракта обновлять этот шаблон в том же коммите. Не дублировать список и описания в README или отдельных справочниках. Не включать рабочие секреты.
