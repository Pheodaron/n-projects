# Работа с проектом

- Соблюдать простоту, идиоматичный Go и feature-first структуру внутри internal.
- Инструменты и основные команды проекта определять в .mise.toml.
- Backend запускать через Compose; собирать образ отдельной командой Dockerfile. Wails остаётся отдельным клиентом.
- Миграции Goose хранить в migrations/ и запускать из корня проекта; не применять их автоматически в backend или отдельном сервисе Compose.

## Документация env

При любом изменении env-контракта (добавление, удаление, переименование, default, обязательность, потребитель или способ передачи) в том же коммите обновлять docs/ENVIRONMENT.md и пользовательский шаблон .env.example. Проверять связанные Compose/mise/CI и примеры README. Для служебных переменных, которые задаются автоматически, достаточно описания в справочнике: не добавлять их в шаблон как пользовательские настройки. Различать адреса хоста и контейнера, пример значения и фактический fallback. Не включать рабочие секреты.

Справочник env оформлять списком: одна переменная — один пункт, краткое назначение, обязательность/default и допустимые значения либо пример формата. Для динамических значений указывать источник (например, model ID из /v1/models); не придумывать конечный набор значений. Не заменять список таблицами и длинными пояснениями.
