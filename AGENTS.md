# Работа с проектом

- Соблюдать простоту, идиоматичный Go и feature-first структуру внутри internal.
- Репозиторий — monorepo: клиенты в apps/, серверные сервисы в apps_back/. У каждого приложения свой mise.toml и Go-модуль; у каждого backend-сервиса свой Dockerfile.
- Общие инструменты и команды определять в корневом mise.toml; команды приложения — в его mise.toml. Desktop использует Wails3 CLI, устанавливаемый mise через go install.
- Backend-сервисы запускать через общий compose.yaml из корня; каждый образ собирать отдельно через Dockerfile сервиса, без build в Compose. Wails остаётся отдельным клиентом.
- Миграции Goose хранить в migrations/ и запускать из корня проекта; не применять их автоматически в backend или отдельном сервисе Compose.

## Документация env

Единственное место описания переменных окружения — комментарии в .env.example. При изменении env-контракта обновлять этот шаблон в том же коммите. Не дублировать список и описания в README или отдельных справочниках. Не включать рабочие секреты.
