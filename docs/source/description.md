# n-projects
**Проект:** Мультисервисная агентная AI-платформа с десктопным клиентом


## 1. Стек технологий и управление окружением

### 1.1. Диспетчер зависимостей и окружения (DevEnv)
Все системные утилиты, компиляторы и рантаймы разработчиков фиксируются и поднимаются через **`mise`** (`mise-en-place`).
* **Конфигурационный файл `.mise.toml` (декларативное окружение):**
  * `go = "1.27.3"` (или новее в рамках минорной ветки)
  * `pandoc = "latest"` (для конвертации документов в текст)
  * `node = "lts"` / `pnpm = "latest"` (сборка фронтенда для Webview)
  * `task = "latest"` (Taskfile для оркестрации локальной сборки)

### 1.2. Базовый программный стек
* **Язык бэкенда и десктопа:** **Go 1.27.3+**
* **Десктоп-фреймворк:** Форк **[Piloswine1/wails](https://github.com/Piloswine1/wails)** с нативной поддержкой 2+ независимых Webview-контекстов в рамках одного процесса.
* **Агентный фреймворк:** **`cloudwego/eino`** (`github.com/cloudwego/eino` + `eino-ext`) — граф-ориентированный Go-фреймворк для оркестрации LLM, субагентов, цепочек и RAG.
* **Базовая модель (Baseline LLM):** **Gemma 4 (12B+)** (через локальный инференс vLLM / Ollama или совместимый OpenAI/Ollama API провайдер в Eino).
* **Конвертер файлов:** CLI-библиотека / сервис-воркер **Pandoc**.

## 3. Детальные спецификации подсистем

### 3.1. Клиентский слой (Desktop: Wails + Multi-Webview)
* **Мульти-контекст:** Использование форка `github.com/Piloswine1/wails` для параллельного рендеринга нескольких Webview:
  * *Webview A:* Основной чат, стриминг текста, отображение цепочки мыслей (*thought chain*).
  * *Webview B:* Вспомогательный контекст (дерево выполнения агентов, превью документов, канбан-панель активных сессий).
* **Событийная модель:** Обмен данными между Webview-окнами через Go Runtime Event Bus (Wails Events) без просадки FPS.
* **Голосовой контур:**
  * Запись аудио в Webview (MediaRecorder API) $\to$ передача бинарного чанка в Go-слой.
  * Синхронное воспроизведение TTS с возможностью немедленной паузы через системный хоткей.
* **OS Notifications:** Отправка нативных системных уведомлений средствами Go при фоновом завершении задач субагентами.

### 3.2. Агентный контур (Core Agent на базе `cloudwego/eino`)
* **Оркестрация на `cloudwego/eino`:**
  * Реализация логики через **Eino Graph (`compose.NewGraph`)**: узлы модели, узлы тулов, пре/пост-процессинг.
  * **Субагенты:** Реализуются как вложенные графы (Sub-Graphs), выполняющиеся параллельно через горутины.
* **Стриминг:** Использование нативных потоковых интерфейсов Eino (`schema.StreamReader`) для сквозного стриминга:
  * Токены генерации модели;
  * Трассировка аргументов вызова тулов;
  * Промежуточные статусы выполнения сценариев.
* **Остановка (Cancellation):**
  * Связка UI-кнопки «Stop» с родительским `context.WithCancel(ctx)`.
  * При триггере отмены Eino штатно прерывает графы исполнения, закрывает стримы и гасит воркеры субагентов без утечки горутин.
* **Human-in-the-Loop (User Response):**
  * Использование прерываний графа (`Eino Interrupt / State Pause`): если инструмент требует подтверждения или ручного ввода, граф сериализует состояние, ждет эндпоинта `Resume(session_id, user_payload)` и продолжает выполнение.
* **Pre-summary Title:**
  * Отдельный легковесный Eino `Lambda`-компонент, запускающийся асинхронно после 1-го ответа пользователя для получения короткого наименования ветки.

### 3.3. Модель и инференс
* **Бейслайн:** **Gemma 4 (12B+)**.
* **Интеграция:** Имплементация интерфейса `model.ChatModel` в Eino с поддержкой Function/Tool Calling в формате схемы Gemma.

### 3.4. Управление пользователями и сессиями
* **Администрирование:** RBAC-контроль (`Admin`, `Member`, `Read-only`), привязка токенов.
* **Сессии:**
  * Каждая сессия хранится в БД с метаданными пользователя.
  * Сессия сохраняет сериализованное состояние графа Eino (`Checkpoints`), что позволяет:
    * восстановить диалог в любой момент;
    * сделать Fork (ответвление) контекста с произвольного шага.

### 3.5. Инструменты (Tools) и Centralized Skill Registry
* **Диспетчеризация:** Централизованный реестр регистрирует тулы в виде `eino.Tool` интерфейсов. В модель передаются только разрешенные и релевантные контексту манифесты (динамическая фильтрация).
* **Типология тулов:**
  1. **Системные (System):**
     * `read_file` — чтение локальных файлов/чанков;
     * `rag_search` — векторный поиск по корпоративным базам знаний;
     * `spawn_subagent` — инициализация дочерней задачи.
  2. **Сценарные (Scenario):**
     * Композитные сценарии («Подготовить сравнительный отчет», «Рефакторинг модуля»), содержащие многошаговые Eino-цепочки с контрольными точками.
  3. **Специализированные (Domain/«как в Илоне»):**
     * Узкие интеграционные тулы (коннекторы к CRM, баг-трекерам, парсерам биржевых/отраслевых сводок).

### 3.6. Обработка файлов и RAG (Pandoc Pipeline)
* **Конвертер документов:**
  * Поддерживаемые форматы: `.pdf`, `.docx`, `.xlsx`, `.rtf`, `.html`, `.epub`.
  * Сервис запускает Pandoc с нормализацией в чистый Markdown/Plaintext.
* **Хранилище и RAG:**
  * Сохранение сырых файлов в S3/MinIO.
  * Чанкование текста и сохранение эмбеддингов через Eino `Retriever` / `Embedding` компоненты в Vector DB (Qdrant / pgvector).

### 3.7. Трейсинг и логирование
* Подключение встроенных коллбеков Eino (`callbacks.Handler`) для логирования в OpenTelemetry:
  * Входной промпт $\to$ задержка (TTFT) $\to$ вызовы инструментов с аргументами $\to$ результат.
* Журналирование всех действий пользователей и агентов для аудита безопасности.

## 4. План развертывания проекта (Quick Start DevEnv)

```bash
# 1. Установка зависимостей окружения через mise
mise install

# 2. Инициализация и сборка Wails-клиента с форком
git clone https://github.com/Piloswine1/wails.git
cd desktop && task build

# 3. Запуск сервисов агента и оркестратора Eino
go run ./cmd/orchestrator
```
