# Переменные окружения

Этот справочник описывает текущие переменные из Go-кода, `deploy/compose.yaml`, `.mise.toml` и тестов. Шаблон для заполнения — [`.env.example`](../.env.example).

## Как загружается конфигурация

1. Скопируйте `.env.example` в `.env` в корне проекта и заполните параметры.
2. Mise читает `.env` через `[env] _.file = ".env"`.
3. Compose получает `.env` явно: `docker compose --env-file .env -f deploy/compose.yaml …`. Переменные окружения shell имеют приоритет над значениями файла при подстановке Compose.
4. Файл `.env` не передаётся контейнеру целиком: backend получает только параметры, перечисленные в `services.backend.environment`.
5. Готовый Wails-клиент сам `.env` не читает. Передайте `BACKEND_URL` и `DEV_TOKEN` в окружение его процесса; например, запуск через `mise exec -- /path/to/desktop` загрузит `.env` из проекта.

`.env` исключён из Git и Docker build context. В репозитории хранится только шаблон с примерами, без рабочих токенов и паролей. Изменение `.env` требует пересоздания соответствующего контейнера через Compose; настройки запущенного процесса не обновляются автоматически.

## Образ и опубликованные порты

| Переменная | Потребитель | По умолчанию | Назначение |
|---|---|---|---|
| `APP_IMAGE` | Compose | `n-projects:local` | Имя и тег готового backend-образа. Должны совпадать с результатом отдельного `docker build -t …` либо существующим registry-образом. Compose не собирает образ. |
| `BACKEND_BIND` | Compose | `127.0.0.1` | Интерфейс **хоста**, на котором публикуется backend. Для доступа с других машин укажите нужный адрес или `0.0.0.0`; для публичного endpoint используйте TLS proxy. |
| `BACKEND_PORT` | Compose | `8080` | Порт backend **на хосте**. Внутри контейнера сервер слушает `8080`. |
| `POSTGRES_PORT` | Compose | `5432` | Порт PostgreSQL **на хосте**, опубликованный на `127.0.0.1`. Внутри Compose PostgreSQL всегда доступен как `postgres:5432`. |

Если изменён BACKEND_PORT, обновите BACKEND_URL клиента. Если изменён POSTGRES_PORT, обновите DATABASE_URL для Goose и TEST_DATABASE_URL для тестов.

## PostgreSQL и миграции

| Переменная | Потребитель | Обязательность | Назначение и пример |
|---|---|---|---|
| `POSTGRES_PASSWORD` | Контейнер PostgreSQL | Обязательна, непустая | Пароль пользователя `nprojects`. В `.env.example` значение `dev` — только пример. Должен соответствовать паролю в обеих строках подключения. |
| `DATABASE_URL` | Goose из корня проекта | Обязательна для миграций | Подключение **с хоста**: `postgres://nprojects:dev@127.0.0.1:5432/nprojects?sslmode=disable`. Используется задачами `migrate`, `migrate:status`, `migrate:down`. |
| `BACKEND_DATABASE_URL` | Compose → backend | Обязательна, непустая | Подключение **из контейнера**: `postgres://nprojects:dev@postgres:5432/nprojects?sslmode=disable`. Compose передаёт его серверу под именем `DATABASE_URL`. |

Обе строки подключения указывают на одну БД через разные сетевые адреса. В текущем Compose фиксированы `POSTGRES_USER=nprojects` и `POSTGRES_DB=nprojects`. Добавление POSTGRES_USER или POSTGRES_DB в `.env` не изменит эти настройки; для другого пользователя/имени БД потребуется согласованное изменение Compose и обеих строк подключения. Специальные символы в пароле должны быть URL-encoded в строках подключения. `sslmode=disable` в примере предназначен для текущего подключения к PostgreSQL в локальном Compose; для внешней БД настройте TLS согласно её требованиям.

`POSTGRES_PASSWORD` применяется официальным образом PostgreSQL при первичной инициализации пустого volume. Изменение этой переменной не меняет пароль в уже существующей БД: его нужно отдельно изменить в PostgreSQL и согласованно обновить строки подключения.

Mise автоматически задаёт Goose `GOOSE_DRIVER=postgres` и `GOOSE_DBSTRING` из `DATABASE_URL`. Вручную добавлять эти переменные в `.env` не требуется. SQL находится в `migrations/`; отдельного сервиса миграций в Compose нет.

```sh
docker compose --env-file .env -f deploy/compose.yaml up -d --wait postgres
mise run migrate
mise run compose:up
```

Сам сервер поддерживает переменную `DATABASE_URL`. Его встроенный fallback — `postgres://nprojects:dev@127.0.0.1:5432/nprojects?sslmode=disable`, но при штатном контейнерном запуске Compose требует `BACKEND_DATABASE_URL` и всегда передаёт её явно.

## Доступ desktop к backend

| Переменная | Потребитель | По умолчанию | Назначение |
|---|---|---|---|
| `DEV_TOKEN` | Backend и Go-слой Wails | Нет; обязательна | Общий непустой bearer token. Клиент отправляет его в ConnectRPC-запросах, сервер проверяет. Замените значение `replace-with-a-random-local-development-token` из шаблона собственным. Это dev-доступ к одному пользователю/workspace, не система аккаунтов. |
| `BACKEND_URL` | Go-слой Wails | `http://127.0.0.1:8080` | Адрес backend **с компьютера клиента**, например `https://agent.example.com`. Не адрес `postgres` или внутреннее имя контейнера. Для удалённого клиента используйте доступный ему hostname и TLS endpoint. |

`DEV_TOKEN` и `LLAMA_API_KEY` — разные ключи для разных соединений. DEV_TOKEN не передаётся модели; LLAMA_API_KEY не передаётся desktop.

Сервер также читает `SERVER_ADDR`, fallback `127.0.0.1:8080`. В Compose она **фиксирована** как `0.0.0.0:8080`, чтобы принимать соединения внутри контейнера. Добавление SERVER_ADDR в `.env` не изменит это значение; публикацией наружу управляют BACKEND_BIND и BACKEND_PORT.

## Подключение к llama.cpp

| Переменная | Потребитель | Обязательность в Compose | Назначение |
|---|---|---|---|
| `LLAMA_BASE_URL` | Backend | Обязательна, непустая | Базовый OpenAI-compatible URL **с `/v1`**, например `http://inference.example:8081/v1`. Backend добавляет `/models` и `/chat/completions`. URL должен быть доступен из контейнера; `localhost` указывает на сам контейнер backend. В URL не допускаются credentials, query и fragment. |
| `LLAMA_MODEL` | Backend | Обязательна, непустая | Точный ID модели из `/v1/models`, а не путь к GGUF. Используется в поле `model` запроса. |
| `LLAMA_API_KEY` | Backend | Необязательна; пустая строка | Ключ авторизации inference-сервиса. При непустом значении отправляется как `Authorization: Bearer …`; при пустом заголовок не добавляется. |

В Go-коде fallback LLAMA_BASE_URL — `http://127.0.0.1:8081/v1`, LLAMA_MODEL — `local`. Compose требует явные значения, поэтому эти fallback не заменяют настройку `.env` при штатном запуске. `/readyz` проверяет, что указанный model ID присутствует в ответе `/models`.

llama.cpp запускается отдельно. Переменных установки модели, пути к GGUF и локального launcher в текущем проекте нет.

## Тесты

| Переменная | Потребитель | По умолчанию | Назначение |
|---|---|---|---|
| `TEST_DATABASE_URL` | Интеграционные тесты Core и миграций | Не задана | URL PostgreSQL **с машины запуска тестов**. Если отсутствует, DB-интеграционные тесты пропускаются. В CI задан явно. Пример: `postgres://nprojects:dev@127.0.0.1:5432/nprojects?sslmode=disable`. |

Тестам нужны права создавать и удалять схемы. Они используют отдельные схемы, а не Core-таблицы рабочей схемы.

```sh
TEST_DATABASE_URL=postgres://nprojects:dev@127.0.0.1:5432/nprojects?sslmode=disable mise run test
```

## Поддержка справочника

При добавлении, переименовании, удалении env-переменной или изменении её обязательности, значения по умолчанию либо потребителя в том же изменении обновляются:

- этот справочник;
- `.env.example` для параметров, которые задаёт пользователь;
- Compose, mise и CI там, где параметр передаётся или используется;
- примеры в README, если меняется порядок настройки.

В таблицах различаются значения примера, fallback Go-кода и настройки, принудительно передаваемые Compose. Реальные секреты в документацию не добавляются.
