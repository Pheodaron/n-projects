# Core prototype

Рабочий каталог: `apps_back/core-prototype`, ветка `core/architecture-review`.
Это отдельный Go-модуль для дальнейшей работы над предоставленным примером.

```text
apps_back/core-prototype/
  cmd/server/
    main.go                  HTTP: /send, /stop, /events
    events.go                подписки HTTP-клиентов
  pkg/agentcore/
    agent.go                 фабрика llama.cpp / Qwen
    engine.go                создание сессий и завершение приложения
    session.go               callbacks TurnLoop и передача событий
    ports.go                 Store и MemoryStore
    types.go                 команды, события и результаты ходов
  go.mod
  go.sum
  mise.toml
  Dockerfile
```

Go 1.27.3, Eino v0.9.23, agenticopenai v0.2.4. Корневого Go workspace и локальных `replace` нет. Существующие server и desktop не изменены.

## Исполнение

`NewSession` создаёт обычный указатель на TurnLoop и запускает его один раз. `Session.Send` вызывает потокобезопасный `Push` и возвращает ошибку, если команда отвергнута; подтверждение preempt не ожидается. `genInput` выбирает один запрос и возвращает остальные в `Remaining`.

`prepareAgent` использует фабрику агента. `onAgentEvents` самостоятельно вычитывает iterator и вызывает `readStream` для потоковых сообщений. Text и reasoning передаются через `publishMessage` и `publish` в функцию `emit`, предоставленную приложением. SQL, Wails и HTTP не входят в Session.

После завершения iterator `Store.SaveTurn` сохраняет сообщения и статус вместе. Ошибки генерации и сборки сообщения сохраняются в результате; частичный ответ имеет статус `failed`, `cancelled` или `preempted`. После ошибки модели сессия может принять следующий запрос. Ошибка сохранения завершает loop; `Wait` позволяет получить причину, последующие отправки отклоняются. Финализация ограничена пятью секундами и не зависит от отменённого контекста генерации.

`Session.Stop` отменяет контекст только наблюдаемого текущего хода. Очередь продолжает выполняться. `Shutdown` завершает loop. Engine регистрирует сессию до запуска и использует канал готовности, чтобы конкурентные обращения получили один экземпляр.

## Подписки и хранение

`EngineConfig.Emit` должен быстро принимать события и поддерживать вызовы разных сессий. В HTTP-примере он подключён к `eventHub.publish`. Один обработчик hub регистрирует подписчиков, рассылает события и закрывает каналы. Отключение клиента не отменяет выполнение агента. При переполнении буфера медленный подписчик отключается.

Новый подписчик получает будущие события. Восстановление уже сгенерированного текста при переподключении в этом упрощённом варианте пока не реализовано.

MemoryStore сохраняет независимые JSON-записи в `sync.Map`, обновляя историю и результат вместе через compare-and-swap. Явных mutex в прототипе нет. Content blocks, включая reasoning, сохраняются; произвольные Go-типы в provider-specific `Extra`/`Extension` при JSON round-trip не восстанавливаются автоматически. `LoadTurns` позволяет прочитать статусы и частичные результаты. Пока `Load` включает также сохранённые частичные сообщения в следующий контекст модели.

Хранилище остаётся в памяти: данные и очередь не переживают перезапуск. SQLite/PostgreSQL, идемпотентность, tools, skills и sub-agents остаются следующими задачами. Автоматические тесты в этот коммит не включены по просьбе пользователя.

## Команды

```sh
cd apps_back/core-prototype
mise trust
mise install
mise run deps
mise run fmt
mise run build
```

`build` собирает отдельный Docker image. Подключение прототипа к общему Compose пока не добавлено. Новых переменных окружения нет: параметры llama.cpp остаются в `main.go`.

Первоначальный анализ исходного примера: [CORE_REVIEW.md](CORE_REVIEW.md). Он описывает состояние до этих исправлений.
